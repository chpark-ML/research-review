# paper-summary

논문 한 편을 **연구자가 5~10분 안에 핵심을 파악**할 수 있는 한국어 상세 요약으로 정리한다. 단순 abstract 번역이 아니라, 논문 전체 구조를 재구성한 참고용 정리본.

## 입력 / 출력

- **입력**: `papers/<slug>/_workspace/paper.txt` (PyMuPDF 추출). 수치·표·그림 캡션 확인이 필요하면 원본 `assets/<file>.pdf`도 참조.
- **출력**: `papers/<slug>/summary.md` (한국어).

## 언어 규약

- 본문은 한국어. **전문용어·메서드명·메트릭명·데이터셋명은 영문 그대로** (예: self-consistency, BM25, MedQA, accuracy). 첫 등장 시 짧은 한국어 풀이를 괄호로 덧붙일 수 있다.
- 과장 금지 — 논문이 주장하지 않은 것을 단정하지 않는다. 저자 주장과 본인 해석을 구분 (예: "저자는 …라고 주장한다", "단, …는 한계").

## 표준 구조 (섹션 순서 고정)

```markdown
# <메서드명> 상세 요약

> 한 줄 메타: 원문 제목 · 저자(소속) · 게재처/연도 · arXiv/코드 링크.

## 0. 서지 정보
표: 제목 | 저자(소속) | 게재처 | 연도 | 분량 | 코드 | 키워드

## 1. 한 줄 요약 & 연구 동기
- **한 줄.** 이 논문이 무엇을 했는가 (정량 결과 1개 포함).
- **배경.** 어떤 문제/한계에서 출발했는가.
- **연구 질문.** 핵심 질문 1~2개.

## 2. 전체 구조
논문 목차를 계층 코드블록으로 (Abstract → §N → Appendix).

## 3. 문제 정의 / 사전 지식
표기·세팅·기존 방법의 한계를 정리.

## 4. 제안 방법
핵심 메커니즘을 구성요소별로. 필요한 수식은 LaTeX(`$...$`)로.
- 각 구성요소: 목적(어느 한계를 푸는가) → 메커니즘 → 비고.

## 5. 이론적/직관적 근거
저자가 제시한 정당화 (해당 시).

## 6. 실험
- Setup: 데이터셋 / 베이스라인 / 백본 / 메트릭.
- Main result: 핵심 수치 표 (요점만).
- Ablation / 분석: 각 구성요소 기여도, 하이퍼파라미터, 효율성.

## 7. 한계 & 향후 연구
저자 명시 한계 + 리뷰어 관점의 추가 관찰(명확히 구분).

## 8. 실무 적용 관점 (도메인 관련 시)
실무 적용 가능성·재현 난이도·도메인 접목 여지. 관련 없으면 생략. (특정 회사·조직명은 적지 않는다.)
```

## 절차

1. **인제스트 읽기** — `_workspace/paper.txt`에서 abstract·intro·method·experiments·conclusion을 정독. 표 수치는 추출 텍스트가 흐트러질 수 있으니 원본 PDF 페이지로 교차 확인.
2. **서지정보 확정** — `meta.yaml`이 있으면 재사용, 없으면 작성.
3. **핵심 수치 수집** — main result, ablation 기여도, 효율성 수치를 정확히. **수치는 절대 추정·반올림 변형 금지** (원문 그대로).
4. **구조 순서대로 작성** — 위 템플릿. 표는 markdown 표.
5. **자기 검증** — §아래 체크리스트.

## 분량 가이드

- 기본: A4 약 3~5페이지 분량 (논문 핵심을 빠짐없이, 군더더기 없이).
- "간략히" 요청 → §0,1,4,6만 압축. "더 자세히" → §4(방법)·§6(실험)을 수식·표까지 확장.

## 검증 체크리스트 (종료 게이트)

```
[ ] 서지정보(제목·저자·게재처·연도) 정확
[ ] 한 줄 요약에 정량 결과 1개 이상 포함
[ ] main result 핵심 수치가 원문과 일치 (추정 금지)
[ ] 제안 방법의 각 구성요소가 "어느 문제를 푸는지" 명시
[ ] 저자 주장 vs 리뷰어 해석 구분
[ ] 메서드명·메트릭명 영문 표기 일관
[ ] 한계 섹션 존재
```

- "방법 부분만 다시 정리"
